## 1. 概述

### 1.1 测试级别定义

| 级别 | 定义 | 限制 |
|------|------|------|
| 黑盒测试 | 不引入任何代码，通过 shell 脚本模拟 AI 行为（写 inbox、执行 run.py、读 outbox 进行断言） | 禁止 `import` 被测模块 |
| 集成测试 | 调用模块的公共方法，全程禁止 mock/打桩，链路必须穿透到数据层（文件系统、daemon TCP、远程 SSH 连接） | 禁止 mock；可引入公共类和方法 |
| 单元测试 | 测试单个公共方法的行为，允许 mock 外部依赖 | 仅允许 mock 外部依赖，不 mock 被测方法本身 |

### 1.2 覆盖原则

- **黑盒覆盖集成**：黑盒测试的场景覆盖对应集成测试场景，集成测试不重复设计已被黑盒覆盖的用例
- **集成覆盖单元**：每个集成测试用例必须覆盖至少一个单元测试场景。如果某集成测试未覆盖任何单元测试，说明该单元测试用例缺失，需补充
- **全面覆盖**：正常场景 + 异常场景，逐模块验收

### 1.3 用例格式

每个用例包含：

```
【测试场景】一句话描述
【前提条件】测试前必须满足的状态
【测试步骤】操作序列
【预期结果】系统应输出的结果
【断言】(伪代码) 具体断言
```

## 2. P1: command_guard.py

### 2.1 单元测试

#### U-P1-01: ALLOW 级 — 普通读命令直接放行

```
【测试场景】安全的只读命令（如 ls、cat、ps）不应被拦截
【前提条件】无
【测试步骤】调用 CommandGuard.check("ls -la")
【预期结果】level=allow, blocked=false
【断言】
  result = guard.check("ls -la")
  assert result.level == "allow"
  assert result.blocked == False
```

#### U-P1-02: WARN 级 — rm 递归删除被警告

```
【测试场景】rm -rf /tmp/logs 应命中 WARN 规则
【前提条件】无
【测试步骤】调用 CommandGuard.check("rm -rf /tmp/logs")
【预期结果】level=warn, blocked=true, reason 含"递归强制删除"
【断言】
  result = guard.check("rm -rf /tmp/logs")
  assert result.level == "warn"
  assert result.blocked == True
  assert "递归强制删除" in result.reason
```

#### U-P1-03: BLOCK 级 — 删除根目录被拦截

```
【测试场景】rm -rf / 应命中 BLOCK 规则
【前提条件】无
【测试步骤】调用 CommandGuard.check("rm -rf /")
【预期结果】level=block, blocked=true
【断言】
  result = guard.check("rm -rf /")
  assert result.level == "block"
  assert result.blocked == True
```

#### U-P1-04: force=true — WARN 放行、BLOCK 不放行

```
【测试场景】force=true 仅放行 WARN，BLOCK 始终拒绝
【前提条件】无
【测试步骤】
  1. CommandGuard.can_execute("warn", force=True)
  2. CommandGuard.can_execute("block", force=True)
  3. CommandGuard.can_execute("allow", force=False)
【预期结果】warn+force→可执行, block+force→不可执行, allow→可执行
【断言】
  assert guard.can_execute("warn",  True)  == True
  assert guard.can_execute("block", True)  == False
  assert guard.can_execute("allow", False) == True
```

#### U-P1-05: 空命令直接拒绝

```
【测试场景】空字符串或纯空格应被拒绝
【前提条件】无
【测试步骤】
  1. CommandGuard.check("")
  2. CommandGuard.check("   ")
【预期结果】level=block, reason="空命令"
【断言】
  assert guard.check("").level == "block"
  assert "空命令" in guard.check("").reason
  assert guard.check("   ").level == "block"
```

#### U-P1-06: BLOCK 优先于 WARN 匹配

```
【测试场景】同时匹配 BLOCK 和 WARN 规则时返回 BLOCK
【前提条件】无。'rm -rf /tmp' 虽然匹配 WARN 的 'rm -rf' 模式，但应该确认 BLOCK 优先匹配的语义
【测试步骤】构造一个不会同时命中两者但能验证优先级的场景
  1. guard.check("dd if=/dev/zero of=/dev/sda")   # 命中 block (dd+of=/dev/sd*) 也碰不到 warn
  2. guard.check("rm -rf /tmp/logs")              # 仅命中 warn
【预期结果】第一条返回 block，第二条返回 warn
【断言】
  assert guard.check("dd if=/dev/zero of=/dev/sda").level == "block"
  assert guard.check("rm -rf /tmp/logs").level == "warn"
```

#### U-P1-07: WARN 级 — sed 原地修改、kill -9、shutdown

```
【测试场景】sed -i、kill -9、shutdown 各命中 WARN
【前提条件】无
【测试步骤】逐一调用 guard.check(...)
【预期结果】全部返回 level=warn, blocked=true
【断言】
  assert guard.check("sed -i 's/a/b/' file.txt").level == "warn"
  assert guard.check("kill -9 1234").level == "warn"
  assert guard.check("shutdown -h now").level == "warn"
```

#### U-P1-08: BLOCK 级 — mkfs、fork bomb、覆盖块设备

```
【测试场景】高危命令各命中 BLOCK
【前提条件】无
【测试步骤】逐一调用
【预期结果】全部返回 level=block
【断言】
  assert guard.check("mkfs.ext4 /dev/sda1").level == "block"
  assert guard.check("> /dev/sda").level == "block"
```

**覆盖率评估**：P1 无集成测试和黑盒测试（纯函数，无数据层/无外部 I/O）。全部场景由 8 个单元测试覆盖。每个 unit test 的断言精确到字段值。

## 3. P4: run.py — 黑盒测试

黑盒测试模拟 AI 行为，不引入任何 Python 模块。通过 shell 脚本顺序执行：写 inbox 文件 → 执行 run.py → 读 outbox 文件 → 断言。

### 3.1 正常场景

#### B-P4-01: 执行命令 — 完整 Write → Run → Read 链路

```
【测试场景】AI 写入命令，执行 run.py，查看 stdout 和 outbox 文件
【前提条件】daemon 已启动且已配置环境 192.168.1.100
【测试步骤】
  1. 写入 inbox/task.json: {"task_id":"task_1","target":"192.168.1.100","command":"echo hello"}
  2. shell 执行: python run.py
  3. 读 outbox/result.json
【预期结果】
  - stdout 输出含 "hello"
  - stdout 末尾含 "[完整结果: outbox/result.json]"
  - outbox/result.json: success=true, exit_code=0, stdout="hello\n"
  - inbox/task.json 被删除
【断言】(伪代码)
  stdout = shell_exec("python run.py")
  assert "hello" in stdout
  assert "[完整结果: outbox/result.json]" in stdout

  result = json_read("outbox/result.json")
  assert result["success"] == True
  assert result["exit_code"] == 0
  assert "hello" in result["stdout"]

  assert not exists("inbox/task.json")
```

#### B-P4-02: 文件上传

```
【测试场景】AI 上传文件到远程
【前提条件】daemon 已启动，本地存在测试文件 C:/tmp/test_upload.txt
【测试步骤】
  1. 写入 inbox/task.json: {"task_id":"task_2","target":"192.168.1.100","upload":{"local":"C:/tmp/test_upload.txt","remote":"/tmp/test_upload.txt"}}
  2. shell 执行: python run.py
  3. 读 outbox/result.json
  4. 远程验证: ssh 192.168.1.100 "cat /tmp/test_upload.txt"
【预期结果】result.json success=true，远程文件内容与本地一致
【断言】
  result = json_read("outbox/result.json")
  assert result["success"] == True
  # 远程验证由外部脚本完成，不在 outbox 中体现
```

#### B-P4-03: 危险命令拦截

```
【测试场景】AI 写入危险命令，run.py 拦截，stdout 显示 BLOCKED
【前提条件】daemon 已启动
【测试步骤】
  1. 写入 inbox/task.json: {"task_id":"task_1","target":"192.168.1.100","command":"rm -rf /"}
  2. shell 执行: python run.py
  3. 读 outbox/result.json
【预期结果】
  - stdout 含 "[BLOCKED]"
  - outbox: blocked=true, level="block"
  - daemon 未收到任何 execute 请求
【断言】
  stdout = shell_exec("python run.py")
  assert "[BLOCKED]" in stdout

  result = json_read("outbox/result.json")
  assert result["blocked"] == True
  assert result["level"] == "block"
```

#### B-P4-04: 危险命令 force=true 放行

```
【测试场景】WARN 命令 + force=true → 放行执行
【前提条件】daemon 已启动
【测试步骤】
  1. 写入 inbox/task.json: {"task_id":"task_1","target":"192.168.1.100","command":"rm -rf /tmp/test_dir","force":true}
  2. shell 执行: python run.py
  3. 读 outbox/result.json
【预期结果】blocked=false，命令被实际执行
【断言】
  result = json_read("outbox/result.json")
  assert result["blocked"] == False
```

#### B-P4-05: 会话管理

```
【测试场景】会话列表查看、断开连接
【前提条件】daemon 已启动，已有至少一条活跃会话
【测试步骤】
  1. 写入 inbox/task.json: {"task_id":"task_3","session":"list"}
  2. shell 执行: python run.py
  3. 读 outbox/result.json 断言 sessions 非空
  4. 写入 inbox/task.json: {"task_id":"task_4","session":"disconnect","target":"192.168.1.100"}
  5. shell 执行: python run.py
  6. 读 outbox/result.json 断言 success=true
【断言】
  result = json_read("outbox/result.json")
  assert len(result["sessions"]) > 0

  # disconnect 后
  result2 = json_read("outbox/result.json")
  assert result2["success"] == True
```

#### B-P4-06: 环境管理

```
【测试场景】env: add→list→remove 完整流程
【前提条件】env_config.json 可读写
【测试步骤】
  1. env: "add"  写入新环境 192.168.1.200 (无需真实可达)
  2. env: "list" 验证新环境出现在列表中
  3. env: "remove" 删除该环境
  4. env: "list" 验证已移除
【断言】
  # add
  result = json_read("outbox/result.json")
  assert result["success"] == True
  # list 含 192.168.1.200
  result = json_read("outbox/result.json")
  assert any(s["target"] == "192.168.1.200" for s in result.get("sessions", [])) or \
         "192.168.1.200" in str(result)
  # remove
  result = json_read("outbox/result.json")
  assert result["success"] == True
```

#### B-P4-06B: 文件下载（黑盒）

```
【测试场景】AI 从远程下载文件
【前提条件】daemon 已启动，远程存在 /tmp/test_download.txt
【测试步骤】

【断言】

  assert read_file("C:/tmp/dl_result.txt") == "expected_content"
```

#### B-P4-06C: as 字段切换凭证

```
【测试场景】同一个环境配置了多组凭证，通过 as 字段选择非默认凭证执行命令
【前提条件】daemon 已启动，环境 192.168.1.100 配置了两组凭证: admin(默认) 和 root
【测试步骤】
  1. 写入 inbox/task.json: {"task_id":"task_7","target":"192.168.1.100","command":"whoami","as":"root"}
  2. shell 执行: python run.py
  3. 读 outbox/result.json
【预期结果】stdout="root"，证明使用了 root 凭证而非默认的 admin
【断言】
  result = json_read("outbox/result.json")
  assert result["success"] == True
  assert "root" in result["stdout"]
```

#### B-P4-06D: 多凭证环境建立独立 session

```
【测试场景】同一 IP 用不同 credential 建立不同 session（session_key 不同）
【前提条件】daemon 已启动，环境有两组凭证 admin 和 root
【测试步骤】
  1. execute(target="192.168.1.100", as="admin", command="whoami")  → 建立 admin session
  2. execute(target="192.168.1.100", as="root",  command="whoami")  → 建立 root session
  3. session: "list"  → 查看会话数
【预期结果】有 2 条 session，分别对应 admin 和 root
【断言】
  result = json_read("outbox/result.json")
  sessions = result["sessions"]
  assert len(sessions) == 2
  creds = [s["credential_name"] for s in sessions]
  assert "admin" in creds
  assert "root" in creds
```

#### B-P4-06E: env update — 更新已有环境

```
【测试场景】更新已有环境的配置
【前提条件】env_config 中已有 192.168.1.200
【测试步骤】
  1. 写入 inbox: {"task_id":"task_8","env":"update","env_name":"192.168.1.200","config":{"port":2222}}
  2. shell 执行 + 读 outbox
  3. env: "list" 验证 port 已变为 2222
【预期结果】success=true，环境 port 已更新
【断言】
  result = json_read("outbox/result.json")
  assert result["success"] == True
```

#### B-P4-06F: env credential_add / credential_remove

```
【测试场景】为已有环境新增凭证、删除凭证
【前提条件】env_config 中已有 192.168.1.200，只有一组凭证
【测试步骤】
  1. env: "credential_add" → 新增 "deploy" 凭证
  2. env: "list" → 验证出现 deploy
  3. env: "credential_remove" → 删除 "deploy"
  4. env: "list" → 验证 deploy 已移除
【断言】

  # list 后校验
  # credential_remove 后校验
```

### 3.2 异常场景

#### B-P4-10: daemon 降级

```
【测试场景】daemon 不可用且重试耗尽 → 降级为直连

  2. shell 执行: python run.py
【预期结果】stderr 含每次重试失败原因 + "降级为直连模式" + "联系管理员"。命令仍能通过直连执行成功
【断言】
  _, stderr, exit_code = shell_exec("python run.py")
  assert "降级为直连模式" in stderr or exit_code == 0
```

#### B-P4-11: escalate 提权流程

```
【测试场景】命令权限不足 → AI 设 escalate=true 重试 → 成功
【前提条件】环境 192.168.1.100 使用非 root 凭证，sudo_password 正确
【测试步骤】
  1. 写入 task.json: {"command":"touch /root/test","escalate":false} → Run → 权限被拒
  2. AI 判断失败 → 重新写入: {"command":"touch /root/test","escalate":true} → Run
  3. 读 outbox
【预期结果】第一步 exit_code≠0；第二步 exit_code=0
【断言】
  result1 = json_read("outbox/result.json")  # escalate=false
  assert result1["exit_code"] != 0

  result2 = json_read("outbox/result.json")  # escalate=true
  assert result2["exit_code"] == 0
  assert result2["success"] == True
```

```
  1. 建立 TCP 连接到 localhost:19522
  2. 发送 JSON-line: {"id":"1","method":"ping","params":{}}

【预期结果】响应含 {"id":"1","result":{"status":"ok"}}

```
