# 测试设计规范

## 测试三级分层

### 黑盒测试
- 禁止引入任何被测代码（禁止 import 被测模块）
- 通过 shell 脚本 / 命令行模拟用户行为
- 在此项目中的"用户"为 AI Agent，行为模式为：写 inbox 文件 → 执行 run.py → 读 outbox 文件 → 断言

### 集成测试
- 引入被测模块的公共方法（访问控制为 public 的方法，禁止调用 `_` 开头的私有方法）
- **全程禁止 mock / 打桩**
- 调用链路必须穿透到数据层（文件系统、网络连接、数据库等），通过返回值或数据层实际状态进行断言

### 单元测试
- 测试单个公共方法的行为
- 允许 mock 外部依赖
- 断言聚焦于该方法对给定输入的输出是否符合预期

## 覆盖原则

1. **黑盒覆盖集成**：黑盒测试覆盖的场景，集成测试不再重复设计
2. **集成覆盖单元**：每个集成测试用例必须覆盖至少一个单元测试场景。如果某个集成测试未覆盖任何单元测试场景，说明对应的单元测试用例缺失，需补充
3. **全面覆盖**：正常场景 + 异常场景，所有模块逐项验收，不可遗漏

## 用例格式

每个用例必须包含：

- **测试场景**：一句话描述
- **前提条件**：测试前必须满足的状态（需要什么环境、什么配置、什么数据）
- **测试步骤**：操作序列，分步编号
- **预期结果**：系统应输出的结果，自然语言描述
- **断言**：用伪代码表示，指导测试代码实现。断言必须精确到具体字段/状态/返回值，不允许模糊

## 非功能性要求

1. 同级别的测试设计之间不重复
2. 不同级别之间形成覆盖关系（黑盒→集成→单元），覆盖缺口需补充
3. 测试设计完成后必须经过覆盖率评估，验收标准：所有功能点（正常+异常）100% 覆盖
4. 输出格式：按模块分组，每个模块内按黑盒→集成→单元顺序排列
5. 文档末尾附覆盖率矩阵表，展示每个用例覆盖了哪些单元测试
6. 测试环境要求单独列出
